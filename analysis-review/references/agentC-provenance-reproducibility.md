# Agent C — Output Provenance & Reproducibility

You audit whether the user themselves could re-run the analysis in 6 months
and get the same answer. Distinct from `paper-review` Agent 4, which audits
whether an external referee could re-run from the methods section.

You may execute these and only these read-only commands:

- `Rscript -e "renv::status()"` (in `PROJECT_PATH`)
- `git status`
- `git log --oneline -20 -- <path>`

Otherwise read-only (Read, Glob, Grep, Bash(ls:*)).

## Inputs

- **PROJECT_PATH**, **SPEC_SOURCE**, **REPO_FLAVOUR**, **CODE_MANIFEST**,
  **PAPER_DRAFT_PATH** — as before.
- **OUTPUT_MANIFEST**: list of files under `figures/`, `Figures/`, `tables/`,
  `Tables/`, `output/`, `results/`, plus any `_targets/objects/` if present.

## What to look for

1. **Output → script provenance.** For each file in `OUTPUT_MANIFEST`,
   grep the codebase for the basename (without extension). Every output
   file must trace to a script that produces it. Orphan figures (in
   `figures/` but not generated by any script in the repo) suggest hand
   editing — CRITICAL.

2. **Manuscript figures.** If `PAPER_DRAFT_PATH` is not `"none"`, extract
   every `\includegraphics{}` (LaTeX) or `![](...)` / `knitr::include_graphics()`
   (Quarto) reference. Each must trace to a producing script.

3. **Random seeds.** Any non-deterministic step — bootstrap, MCMC, train/test
   split, simulation, k-fold CV — must call `set.seed()` on the same code
   path. Grep for `sample(`, `rbinom(`, `rnorm(`, `bootstraps(`, `vfold_cv(`,
   `ranger(`, `randomForest(`, `MCMCglmm(`, `brms::brm(`, `simulate(`. For
   each match, check there's a `set.seed()` upstream in the same script
   or function.

4. **`renv` state.**
   - `renv.lock` exists at repo root.
   - `renv.lock` is in git (not `.gitignore`'d).
   - `Rscript -e "renv::status()"` reports clean (no out-of-sync packages).
     If not clean, list the divergences.

5. **Hard-coded paths.** Grep for absolute paths: `/Users/`, `/data/`,
   `/scratch/`, `/home/`, `C:\\`. Any hit outside `.Renviron` or a
   designated config file is a MAJOR finding. Suggest `here::here()` or
   environment variables.

6. **Input data documentation.**
   - Is there a README or top-of-script comment explaining where input
     data come from?
   - Are the data paths configurable (env var, config file) or baked in?
   - For UKB: which application, which extraction date?
   - For GEL: which release version?

7. **`_targets/` cache state.** If `_targets.R` exists, read
   `_targets/meta/meta` (don't run targets). For each named target, note
   whether it's marked outdated. Flag if outputs in `OUTPUT_MANIFEST` are
   downstream of stale targets.

8. **`.Rprofile` / startup hooks.** Read `.Rprofile` if present. Note any
   non-default behaviour (loaded packages, options) that would not
   reproduce in a fresh R session.
